# 🥳 深大选课 · 自动抢课助手（网页版）

在选课页面上挂一个浮动面板，自动轮询**所有分页**，一发现课程有余量就立刻点「选课」，
弹窗自动确认，抢到后声音 + 桌面通知 + 标签页标题闪烁提醒。

适用页面：`https://ehall.szu.edu.cn/yjsxkapp/sys/xsxkapp/xsxkHome/gotoChooseCourse.do`

---

## 一、安装

### 方式 A：装成 Edge 扩展（不用装油猴，推荐）

1. Edge 地址栏输入 `edge://extensions/` 回车。
2. 打开左下角的 **「开发人员模式」**（Developer mode）开关。
3. 点 **「加载解压缩的扩展」**（Load unpacked）。
4. 选中本项目里的 **`edge-extension` 文件夹**（选文件夹本身，不要进去选文件）。
5. 列表里出现「深大研究生选课 · 自动抢课助手」就装好了。
6. 打开选课页面，右上角出现黑色面板。

几点说明：
- 开发人员模式要一直开着，关掉扩展会被停用。
- Edge 每次启动可能弹一个「关闭开发人员模式扩展」的提示，点 **保留 / 取消** 即可。
- 只在 `ehall.szu.edu.cn` 上生效，其它网站不加载。
- 改了脚本后跑一下 `node build.js` 同步，再到 `edge://extensions/` 点该扩展的**刷新**按钮。

Chrome 同理，入口是 `chrome://extensions/`。

### 方式 B：油猴脚本

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/) 扩展（Chrome / Edge 都行）。
2. 点扩展图标 → **添加新脚本**。
3. 把编辑器里原有内容全删掉，粘贴 `szu-auto-course.user.js` 的**全部内容**。
4. `Ctrl+S` 保存。

### 方式 C：控制台临时用（什么都不装，刷新就没了）

1. 在选课页面按 `F12` → 切到 **Console / 控制台**。
2. 如果是第一次用，先在控制台里输入 `allow pasting` 回车（浏览器的安全提示）。
3. 把 `szu-auto-course.user.js` 全部内容粘贴进去，回车。

> 三种方式跑的是同一份代码，选一种就行，别同时装两种（会出现两个面板）。

## 二、使用步骤

1. **先把页面本身弄到位**：选好学期、课程性质等筛选条件，点「查询」，让待选课程列表正常显示出来。
   脚本是在你当前这个列表上工作的，它不会替你改筛选条件。
2. 点面板上的 **「扫描诊断」**，看日志里的识别结果：
   - 表头是不是完整列出来了
   - 前 5 条课程的「容量 / 已选 / 余量」是不是和页面上一致
   - 总页数对不对
   识别正确了再往下走。**这一步别跳过**。
3. 可选提速：把页面上的 **「是否已满」筛选成 `否`** 再查询，列表里就只剩有名额的课，
   一轮扫得快，也少很多注定失败的点击。（研选课页面没有「每页条数」下拉框，
   「每页最大」这个按钮在这个页面上用不上，会提示找不到。）
4. 设置模式：
   - **所有有余量的课** —— 只要列表里哪门课有余量就抢（对应你说的「只要有容量就自动抢」）
   - **仅关键词匹配** —— 只抢指定的课，在「包含」里填课程名 / 课程号 / 老师，逗号分隔
5. 点 **「开始抢课」**。想先看看效果不真点，就勾上「试运行(不点击)」。

抢到会有提示音 + 桌面通知 + 标题闪「★★ 抢到课了 ★★」。

## 三、面板参数

| 项 | 说明 |
|---|---|
| 模式 | `所有有余量的课` / `仅关键词匹配` |
| 包含 | 关键词，逗号分隔，匹配整行文字（课程名、课程号、老师都算） |
| 排除 | 命中这些词的课直接跳过，两种模式下都生效 |
| 间隔 | 每轮之间等多久，默认 1500ms，最低 500ms |
| 翻页停顿 | 翻到下一页后等多久再扫，默认 400ms |
| 换课停顿 | 一门课失败后，隔多久点下一门，默认 500ms |
| 等提示 | 点完选课后最多等多久来判断成没成，默认 3500ms |

后三项在面板的 **「▸ 时间微调」** 里，点一下展开。

「等提示」是影响速度最大的一项：调小跑得快，但网慢时可能没等到结果就当失败
（不要紧，下一轮还会重试，而且脚本会用页面变化兜底判断）；网络卡就往大调。
| 自动确认弹窗 | 点选课后自动点「确定」，默认开 |
| 余量认不出也点 | 余量解析失败时也点一下试试。默认关，开之前先看诊断结果 |
| 抢到就停止 | 抢到一门就停。只想要某一门时勾上 |
| 声音提醒 | 成功时响三声 |
| 试运行(不点击) | 只报告「这门可以抢」，不真的点，用来验证识别是否正确 |

容量列写成 `300/161` 这种一格两个数的，脚本按「大的是容量、小的是已选」来算，
所以不管系统写成 容量/已选 还是 已选/容量 都不用管顺序。

设置会存在浏览器里，下次打开自动恢复。

面板标题栏可以拖动，点右上角 `—` 收起。

## 五、排查

**面板没出来**
- 扩展方式：到 `edge://extensions/` 确认扩展是「已启用」，然后刷新选课页面。
- 油猴方式：确认脚本是启用状态。
- 面板是有条件挂载的：地址里带 `xkapp`，或者页面上已经出现「选课」按钮，才会显示。
  如果列表还没查询出来，先点页面的「查询」，等几秒面板就会出现（会重试 20 次，约 30 秒）。
- 页面在 iframe 里也没关系，脚本会自动穿透去找课程表。

**诊断说「选课按钮 0 个」**
- 先确认页面上确实已经列出了待选课程（不是空列表）。
- 学校可能把按钮文字改了（比如「志愿」「加入志愿」）。把诊断日志复制给我，我加上对应文字。

**余量识别不出来**
- 诊断里会直接列出前 5 条的容量、已选、余量，和页面上对一眼就知道对不对。
- 如果余量算出负数，脚本会当成「未知」并在日志里说明，不会把有位的课当没位跳过。
- 把诊断日志（点「复制日志」）发我，按你们页面的表头调正则。

**课选上了，但面板「抢到」还是 0**
- 说明脚本没认出这次成功。它会用三种方式判断：系统提示文字、那一行变成「退课」、
  那门课从可选列表里消失。三种都没命中才算失败。
- 判成失败不会有实际损失，下一轮还会重试，届时系统会回「已经选过」，脚本记下后不再重复。
- 如果经常这样，把日志发我，我按你们系统的成功提示再调。

**一直在抢某门永远抢不到的课**
- 返回「容量已满」的会一直重试，这是应该的。
- 返回「时间冲突」「学分超限」这类的，脚本会自动记下来，本次运行内不再重试。
- 带「冲突」标记的课如果压根不想要，在「排除」里填 `冲突`。

**点了没反应 / 弹窗没自动确认**
- 确认「自动确认弹窗」是勾上的。
- 如果确认框长得比较特别，日志里会停在「没抓到系统提示」，把日志发我。

**一直提示「本轮 N 页里没有符合条件的待选课程」**
- 关键词模式下多半是关键词写错了，或者课程列表本身是空的。

**跑着跑着停了**
- 日志出现「登录已失效」→ 重新登录后再点开始。
- 连续 5 次异常会自动停，日志里有原因。

**切到别的标签页后变慢**
- 脚本已经用 Worker 定时器绕开浏览器的后台限流。
- 但页面自己的请求/渲染仍可能被浏览器降速，真要抢的时候还是把这个标签页放前台最稳。

## 六、几点说明

- 脚本做的都是你手动也能做的操作（点选课、点确定、点翻页），只是替你不停地重复。
- 间隔别设太低。默认 1500ms 已经够用，调到几十毫秒对成功率没帮助，只会给服务器添堵，也更容易被风控。
- 抢课规则以学校研究生院的规定为准，用之前自己确认一下学校是否允许，后果自负。
- **重要**：这个脚本的元素识别是按常见选课系统的结构写的，我没有你们系统的账号，
  只在仿真页面上验证过全流程。所以**第一次务必先点「扫描诊断」**，
  识别不对就把日志发我，按真实页面调一版，两三分钟的事。
