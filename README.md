# 🥳 深大自动抢课插件

在选课页面右上角挂一个浮动面板，轮询**全部分页**，发现有余量就立刻点“选课”，
确认弹窗自动点掉，抢到后用提示音、桌面通知和标签页标题闪烁提醒。

可选开启掉线自动重登：会话过期后自动填回账号密码，把验证码图交给视觉大模型识别，
登录后再进选课页继续抢。

适用页面：

- 登录页 `https://ehall.szu.edu.cn/yjsxkapp/sys/xsxkapp/*default/index.do`
- 选课页 `https://ehall.szu.edu.cn/yjsxkapp/sys/xsxkapp/xsxkHome/gotoChooseCourse.do`

---

## 一、安装

三种方式跑的是同一份代码，选一种即可。同时装两种会出现两个面板。

### 方式 A：Edge / Chrome 扩展（推荐）

1. 地址栏输入 `edge://extensions/`（Chrome 是 `chrome://extensions/`）。
2. 打开左下角的**开发人员模式**。
3. 点**加载解压缩的扩展**，选中项目里的 `edge-extension` 文件夹（选文件夹本身）。
4. 打开选课页面，右上角出现面板。

注意：

- 开发人员模式需要一直开着。
- Edge 每次启动可能提示关闭开发人员模式扩展，选择保留。
- 只在 `ehall.szu.edu.cn` 上加载。
- 改过主脚本后跑 `node build.js` 同步，再到扩展页点该扩展的**刷新**。

### 方式 B：Tampermonkey 油猴脚本

1. 装 [Tampermonkey](https://www.tampermonkey.net/) 扩展。
2. 扩展图标 → 添加新脚本，清空编辑器，粘贴 `szu-auto-course.user.js` 全部内容。
3. `Ctrl+S` 保存。

### 方式 C：控制台临时用

1. 选课页面按 `F12` 切到 Console。
2. 首次使用需先输入 `allow pasting` 回车。
3. 粘贴 `szu-auto-course.user.js` 全部内容，回车。刷新页面即失效。

这种方式调不了外部接口（见 [5.4 跨域](#54-跨域)），自动登录多半用不了。

## 二、开始抢课

1. **先把页面本身弄好**：选好学期、课程性质等筛选条件，点“查询”，让待选课程列表正常显示。
   脚本在当前这个列表上工作，不会替你改筛选条件。
2. 点面板的**扫描诊断**，核对日志里的识别结果：表头是否完整、前 5 条课程的容量/已选/余量
   是否和页面一致、总页数对不对。识别正确再往下走，这一步不要跳过。
3. 可选提速：把页面的“是否已满”筛选成`否`再查询，列表里就只剩有名额的课，一轮扫得更快。
   （研选课页面没有每页条数下拉框，面板上的“每页最大”按钮在这个页面用不上。）
4. 选模式：
   - **所有有余量的课** —— 列表里任何一门有余量就抢
   - **仅关键词匹配** —— 只抢指定的课，在“包含”里填课程名 / 课程号 / 老师，逗号分隔
5. 点**开始抢课**。只想看识别效果不真点，勾上“试运行(不点击)”。

抢到会响提示音、发桌面通知，标题闪 `★★ 抢到课了 ★★`。

## 三、面板参数

| 项 | 说明 |
|---|---|
| 模式 | `所有有余量的课` / `仅关键词匹配` |
| 包含 | 关键词，逗号分隔，匹配整行文字（课程名、课程号、老师都算） |
| 排除 | 命中这些词的课直接跳过，两种模式下都生效 |
| 间隔 | 每轮之间等多久，默认在 1200~2500ms 之间随机取 |
| 翻页停顿 | 翻页后等多久再扫，默认 400ms |
| 换课停顿 | 一门课失败后隔多久点下一门，默认 500ms |
| 等提示 | 点完选课后最多等多久判断成败，默认 3500ms |
| 自动确认弹窗 | 点选课后自动点确定，默认开 |
| 余量认不出也点 | 余量解析失败时也点一下试试，默认关 |
| 抢到就停止 | 抢到一门就停 |
| 声音提醒 | 成功时响三声 |
| 试运行(不点击) | 只报告可抢，不真的点 |
| 登录后自动继续 | 掉线重新登录后接着上次进度抢 |
| 掉线自动登录 | 见[第五节](#五掉线自动登录) |

后四个时间项在**▸ 时间微调**里，点一下展开。

间隔不是固定节拍：每轮在上下限之间随机取，翻页和换课停顿各带 ±25% 抖动。

“等提示”对速度影响最大。调小跑得快，但网慢时可能没等到结果就当失败——下一轮还会重试，
而且脚本会用页面变化兜底判断，所以代价不大；网络卡就往大调。

容量列写成 `300/161` 这种一格两个数的，按“大的是容量、小的是已选”解析，
所以系统写成容量/已选还是已选/容量都不影响。

设置存在浏览器里，下次打开自动恢复。面板标题栏可拖动，右上角 `—` 收起。

## 四、正式开抢前先自检

不想一上来就真点，有两个不会产生任何实际操作的办法：

**扫描诊断。** 只读页面并把识别结果打进日志，不点任何按钮。重点核对：

- 表头是否被完整列出
- 前 5 条课程的容量 / 已选 / 余量是否和页面显示一致
- 总页数对不对
- 第一行会写明当前页面判定结果（在不在选课页）、有没有找到“我的选课”入口

**试运行(不点击)。** 勾上后正常跑轮询，发现可抢的课只写日志不点击。
用来确认筛选条件、关键词和余量识别都符合预期。

配了自动登录的话，再去登录页点一次**测试识别**，确认验证码识别结果和大小写都对。
这三步都对了再取消勾选、正式开抢。

## 五、掉线自动登录

抢课经常一挂几个小时，中途会话过期是常事。开启后掉线不用管：脚本自动填回账号密码，
把验证码图发给视觉大模型识别，填码登录，再点“我的选课”进选课页继续抢。

整条路径是：登录页 `.../*default/index.do` → 门户首页（**地址不变**）→ 点“我的选课”
→ 选课页 `.../xsxkHome/gotoChooseCourse.do`。在登录页上点“开始抢课”也会直接触发登录，
不必先手动登进去。

默认关闭，填好凭据后自己勾上。

### 5.1 配置

面板上点开**▸ 自动登录 / 验证码识别**，填学号、密码、API Key，勾上**掉线自动登录**。

填完点**测试识别**：它会拿当前页面上的验证码图，用三种处理各识别一次并分别列出结果，
对照图片就能看出哪种准。这个按钮要在**登录页**上点，选课页没有验证码图。

| 项 | 说明 |
|---|---|
| 最多试 | 一次掉线里最多重试几轮登录，默认 8。每轮换一张新验证码 |
| 交叉验证 | 一张验证码用几种处理交叉比对，默认 2，最多 3。见 [5.3](#53-识别不准怎么办) |

不想每次重装都填一遍，可以写进 `szu-auto-course.user.js` 顶部的 `PRESET`：

```js
var PRESET = {
  user: '',        // 学号
  pass: '',        // 密码
  key:  ''         // API Key
};
```

> ⚠️ 写在这里是**明文**，而且 `node build.js` 会把这份代码原样复制进
> `edge-extension/content.js`，磁盘上会有不止一份。
> 填了就不要把这个目录分享出去，更不要提交到 git。
>
> 面板里存的那份同样是明文（浏览器 localStorage），公用电脑用完点**清除账号密码**。
> 面板里改过之后以面板为准，`PRESET` 只在没在面板上动过时用来打底。

### 5.2 服务商与模型

下拉框预置了几家，都是 OpenAI 的 `chat/completions` 格式。默认**硅基流动** +
`Qwen/Qwen3-VL-30B-A3B-Instruct`。

这个默认值是拿手写体带删除线的验证码实测挑的，同一批 8 张图：

| 模型 | 认对 | 大小写 | 平均耗时 |
|---|---|---|---|
| `Qwen/Qwen3-VL-30B-A3B-Instruct` | 8/8 | 全对 | ~950ms |
| `Qwen/Qwen3-VL-32B-Instruct` | 8/8 | 全对 | ~6.6s |
| `Qwen/Qwen3-VL-8B-Instruct` | 8/8 | **5/8 错** | ~770ms |

8B 会把 `64F7` 读成 `64f7`、`TBXZ` 读成 `tbxz`。验证码只要区分大小写它就基本没法用，
省那 200ms 不划算。

换别家就在下拉框里选，“接口”和“模型”留空即用该家默认值，也可以自己填。
各家模型名变动频繁，报“模型不存在 / 已禁用”就去服务商控制台查当前名称，
填进“模型”框后用**测试识别**验一遍，顺便核对大小写。

### 5.3 识别不准怎么办

这个系统的验证码固定 **4 位字母或数字**。脚本拿这个约束做了两层容错，
而且都发生在**提交之前**——服务端那张图提交后才作废，所以这两层都不额外消耗验证码。

**位数校验。** 模型返回 3 位、5 位或夹了标点汉字的，不用提交就知道错，直接换下一种处理，
省掉一整轮“提交 → 被打回 → 换图 → 重认”。

**交叉验证。** 把同一张验证码做几种不同处理，各识别一次再比对：

| 处理 | 说明 |
|---|---|
| 放大 | 等比放大到 320px 宽左右。验证码图常见只有 100x34，原尺寸容易认岔 |
| 放大 + 对比 | 在放大基础上把灰度往两头拉，压掉背景底色和干扰线 |
| 原尺寸 | 原图直接发 |

按上表顺序识别，**前两种结果一致就直接采用，不问第三种**；三种都不一致时按出现次数最多的提交。
“交叉验证”填几就最多用前几种，填 1 表示只用“放大”。

> 不用“同一张图问三遍取多数”，是因为没用：这类接口跑在 `temperature=0` 上，
> 同一张图连问三次答案完全一样（实测），纯属白等。必须换输入，模型犯的错才可能不同。

最后一层：真提交后被服务端打回“验证码错误”，脚本换一张新图重来，最多重试“最多试”设定的轮数。

> 上面几种处理是拿合成验证码量出来的（放大 8/8、放大+对比 8/8、原尺寸 6/7），
> 真实验证码带干扰线会更难。具体哪种更准请用**测试识别**自己看。
> 三种都认不出来，多半是这个模型吃不下该验证码，换一个视觉模型。

### 5.4 跨域

学校页面上直接请求大模型接口会被浏览器 CORS 挡掉，脚本按安装方式选通道：

| 安装方式 | 通道 | 能否调通 |
|---|---|---|
| Edge/Chrome 扩展 | 后台 `background.js` 转发 | ✅ |
| 油猴 | `GM_xmlhttpRequest` | ✅ |
| 控制台粘贴 | 页面自己的 `fetch` | ⚠️ 取决于服务商 |

> 硅基流动实测允许浏览器直连（响应带 CORS 头），控制台方式也能调通，但别家不一定。
> 扩展和油猴这两条是稳的。

日志开头会写明当前用的哪条通道。用**自定义服务商**时还要放行它的域名：

- 扩展：把域名加进 `edge-extension/manifest.json` 的 `host_permissions`，再到扩展页点刷新。
- 油猴：脚本头加一行 `// @connect 你的域名`。

### 5.5 两条安全线

- **密码错立刻停手。** 页面回“用户名或密码错误”这类提示时，脚本马上关掉自动登录并报警，
  绝不重试——拿错密码反复撞会被学校锁账号。改正后重新点“开始抢课”。
- **只有验证码错才重试。** 换一张图重新识别，最多重试“最多试”设定的轮数（默认 8），
  仍失败就退回等手动登录。

### 5.6 登录后自动进选课页

登录成功后落在门户首页而不是选课页，需要点一下“我的选课”（页面上的 `#courseBtn`）。
脚本每轮开头都会检查，不在选课页就先点这个入口，点完轮询等课表出现（最多 8 秒），
而不是固定睡一段时间。点三次仍进不去才改为直接跳选课页地址。

所以不管是刚登录完落在首页，还是中途被打回首页，都能自己回到选课页。

判断“是不是选课页”不能只看页面上有没有 `<table>`——门户首页的通知公告本身就是表格。
脚本要求页面上有真的“选课”按钮，或者表头含容量/余量/已选/课程号这类字样。

> 门户首页和登录页是同一个地址，所以判断“有没有掉线”只看**页面上有没有可见的密码框**，不看地址。

### 5.7 一直转圈也算掉线

会话在后台过期时，页面常常不弹“请重新登录”，而是接口一直不回、loading 遮罩摘不掉，
表现就是一直转圈。脚本盯着这个：连续转圈超过“转圈超 N 秒”（默认 25）就按掉线处理，
直接跳回登录页重登。嫌太敏感就把秒数调大。

## 六、排查

**面板没出来**

- 扩展方式：到扩展页确认已启用，然后刷新选课页面。
- 油猴方式：确认脚本处于启用状态。
- 面板是有条件挂载的：地址里带 `xkapp`、页面上出现“选课”按钮、或者页面上有登录框，才会显示。
  列表还没查询出来的话，先点页面的“查询”，等几秒面板就会出现（会重试 20 次，约 30 秒）。
- 页面在 iframe 里也没关系，脚本会穿透查找。

**诊断说“选课按钮 0 个”**

- 先确认页面上确实列出了待选课程。
- 学校可能改了按钮文字（比如“志愿”“加入志愿”），在脚本的 `GOOD_BTN` 正则里补上即可。

**余量识别不出来**

- 扫描诊断会列出前 5 条的容量、已选、余量，和页面对照即可判断。
- 余量算出负数时脚本会当成未知并在日志里说明，不会把有位的课当没位跳过。
- 表头和常见写法不一致时，调整 `parseRow` 里的表头正则。

**课选上了但面板“抢到”还是 0**

- 说明没认出这次成功。脚本用三种方式判断：系统提示文字、那一行变成“退课”、
  那门课从可选列表消失。三种都没命中才算失败。
- 判成失败没有实际损失，下一轮还会重试，届时系统会回“已经选过”，记下后不再重复。

**一直在抢某门永远抢不到的课**

- 返回“容量已满”的会一直重试，这是预期行为。
- 返回“时间冲突”“学分超限”这类的会被记下，本次运行内不再重试。
- 完全不想要的课，在“排除”里填关键词。

**点了没反应 / 弹窗没自动确认**

- 确认“自动确认弹窗”已勾上。
- 确认框结构特殊时日志会停在“没抓到系统提示”，需要在 `CONFIRM_SEL` 里补选择器。

**一直提示“本轮 N 页里没有符合条件的待选课程”**

- 关键词模式下多半是关键词写错，或者课程列表本身是空的。
- 也可能是没进选课页。点**扫描诊断**，第一行会写明当前页面判定结果和有没有找到“我的选课”入口。

**跑着跑着停了**

- 日志出现“掉线了”：开了自动登录就等它自己登；没开就手动登录，之后会自动接着抢。
- 连续 5 次异常会自动停，日志里有原因。

**自动登录一直失败**

先在登录页点**测试识别**，把问题分开看：

- “接口返回 4xx” → Key 或模型名不对，见 [5.2](#52-服务商与模型)。
- “请求发不出去，多半是 CORS” → 用的是控制台粘贴方式，换扩展或油猴。
- “几种处理都没读出 4 位验证码” → 这个模型认不动该验证码，换一个视觉模型。
- “几种处理结果不一致” → 偶尔出现正常；一直出现说明模型把握不大，把“交叉验证”调到 3 或换模型。
- “点了登录但没等到结果” → 页面的报错提示没被识别，需要在 `LOGIN_ERR` 正则里补关键词。

**面板上填的账号密码不见了 / 又冒出来了**

- 面板里的值存在浏览器 localStorage，换浏览器或清了站点数据就没了。
- 点过“清除账号密码”之后 `PRESET` 也不会再回填，除非重新在面板里填一次。

**切到别的标签页后变慢**

- 脚本用 Worker 定时器绕开了浏览器的后台限流。
- 但页面自身的请求和渲染仍可能被降速，真要抢的时候把这个标签页放前台最稳。

## 七、说明

- 脚本做的都是手动也能做的操作（点选课、点确定、点翻页），只是替你重复。
- 间隔不要设太低。默认值已经够用，调到几十毫秒对成功率没有帮助，只会增加服务器压力，
  也更容易触发风控。
- 开启自动登录会把密码和 API Key 以明文存在本机。介意就别开，或者用完点“清除账号密码”。
- 元素识别是按这个选课系统的结构写的。学校改版后可能失效，
  真实页面第一次使用务必先点**扫描诊断**；启用自动登录前，先在登录页点**测试识别**。
- 抢课规则以学校研究生院规定为准。是否允许使用这类自动化工具（包括自动识别验证码），
  使用前请自行确认，风险自负。
